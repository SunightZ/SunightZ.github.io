# 录制参数

主页最上方是「参数预览」：当前要用的分辨率、帧率、编码格式、码率模式与声音开关都摊在那里，改完立刻反映出来。

## 画面

| 参数 | 范围 | 说明 |
| --- | --- | --- |
| 分辨率 | 128 ～ 7680 内的偶数 | 宽高都要是偶数，编码器要求 |
| 帧率 | 1 ～ 屏幕最高刷新率 | 例如 120 Hz 屏幕可到 120 FPS；静态画面不保证持续生成这么多帧 |
| 码率 | 1 ～ 100 Mbps | 数值越高画面越细腻、文件越大 |
| 编码格式 | H.264 / H.265 | H.265 同画质下体积更小，但老设备解码兼容性略差 |
| 关键帧间隔 | 1 ～ 10 秒 | 越小越容易拖动定位，体积略大 |
| 码率模式 | VBR / CBR | VBR 平均码率更省，CBR 码率恒定适合直播推流场景 |
| 录制方向 | 自动 / 横屏 / 竖屏 | 自动在开始时按当时屏幕方向确定 |

## 画面设置

- **区域录制**：只录选中区域，见[区域录制](./region.md)。
- **前置摄像头**：录制时叠加可拖动的前置摄像头小窗，需要相机权限与悬浮窗权限。
- **显示触摸位置**（完整版）：录制中显示点按反馈，方便教学演示。
- **动态帧率 / 动态码率**：按画面变化自动收敛，静态画面下更省电、文件更小。

## 参数与设备能力

参数上限不等于设备保证支持：真正可用的分辨率、帧率、码率由设备的硬件编码器决定。

- 应用在开始录制前会向编码器要一份实际支持的组合，超出能力时**明确报错**，而不是录出一堆坏帧。
- 首次进入应用时会按设备能力把默认值收敛到受支持的最高一档（先尺寸、再帧率、最后码率）。
- 模拟器上的软件编码器经常「自称支持」某些模式，实际会失败——所以判断方式是拿真机试。

## 方向与尺寸

- 横竖屏切换时，捕获尺寸跟随屏幕，OpenGL 负责把画面旋转并铺满固定尺寸的视频：竖屏录制时横屏内容会侧转显示，不会缩成中间一条。
- 自定义宽高比与屏幕不一致时会拉伸适配。
