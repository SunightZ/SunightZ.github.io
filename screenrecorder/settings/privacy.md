# 数据与隐私

这一页按源码记录应用**实际**会处理哪些信息、什么时候联网、什么会离开设备。

<div class="sr-note">
<strong>注意：本页记录的是完整版（含 Root / Shizuku 采集与高级版激活）的行为。</strong>精简版没有 Shizuku / Root 采集，因此没有下文的激活校验与心跳链路，联网行为只剩 FFmpeg 运行库下载一项。站内<a href="/privacy">隐私政策</a>是面向精简版的文本，两者的差异见本页末尾。
</div>

## 完全留在本机的部分

以下内容**不会**离开设备，代码中也没有对应的上传调用：

| 内容 | 位置 |
| --- | --- |
| 录制的视频与音频 | 你选择的保存位置，或应用私有目录 |
| 标注截图 | `Pictures/ScreenRecorder` |
| 相册里的视频 | 只读取你选中/展示的那些，用于显示与播放 |
| 麦克风与摄像头内容 | 仅写入录制文件 |
| 触摸坐标 | 仅用于当帧绘制，不保存、不写入文件 |
| 崩溃报告 | 应用私有目录的 `last_crash.txt` |
| 全部设置与配置 | 应用私有偏好 |

### 崩溃报告

应用会捕获 Java 层的未捕获异常（任意线程），记录时间、线程名、包名、应用版本、Android 版本与 SDK、厂商、型号、堆栈以及最多 5 层 cause，写入应用私有目录的 `last_crash.txt`。

同时会发一条系统通知「小白录制发生异常」，点击打开查看页，页面上有「复制」与「分享」两个按钮。**只有你主动点「分享」时，报告才会离开设备。**关闭查看页会删除文件。

覆盖不到的情况：原生崩溃（FFmpeg 等 `.so` 的 SIGSEGV / SIGABRT）、ANR（看门狗超时而非异常）、系统因内存回收进程、以及特权采集进程里的崩溃——后者不跑应用的 Application。

### 机身倾斜角度

底部导航栏的毛玻璃与折射效果会随机身倾斜轻微变化，因此界面需要读取旋转矢量传感器：

- 仅在界面显示期间读取，界面离开时立即注销
- 数值只用于当帧绘制，**不保存、不写入文件、不上传**
- 不与任何信息组合用于识别你

不想让界面读取时，可以不进入使用毛玻璃效果的界面。

## 会联网的三处

### 1. FFmpeg 运行库下载

首次使用视频工具箱时，从公开地址下载运行库压缩包（主地址 + 备用地址），下载后按内置的 SHA-256 逐个文件校验。

这次下载不包含你的任何文件或个人信息。传输层与文件托管方会按行业惯例记录常规网络信息（IP 地址、User-Agent、访问时间），应用自身不收集、不保存这些信息。

**不使用视频工具箱，就不会发生这次下载。**

### 2. 高级版激活与心跳

完整版的 Root / Shizuku 采集需要激活校验。应用会与授权服务器通信，完成会话建立、卡密验证、设备绑定与心跳保持。

<div class="sr-note">
<strong>传输层不一致，需要留意。</strong>应用侧（Kotlin / OkHttp）走 HTTPS；但 Root / Shizuku 的录制进程是一个独立的原生可执行文件，它自带一套授权实现，其服务器地址是 <strong>http://</strong>（明文，80 端口），没有 TLS、没有证书校验。载荷本身经过 ChaCha20-Poly1305 加密（被动监听看不到内容），但<strong>没有传输层的服务端身份认证</strong>，存在中间人风险。两处都没有配置证书固定（CertificatePinner）。
</div>

这条路径上会离开设备的信息：

| 信息 | 说明 |
| --- | --- |
| 设备指纹 | 由 30 多项硬件标识（含序列号、存储芯片标识、SoC 序列号等）计算出的 SHA-256 |
| 卡密 | 你输入的激活码原文 |
| 卡密哈希 | 卡密的派生哈希 |
| 应用版本号 | 用于版本检查 |
| 机型与系统版本 | 每次请求的 User-Agent 里包含厂商、型号与系统版本 |
| IP 地址 | 传输层必然暴露 |

**不会**上传：录制的视频与音频、屏幕内容、相册视频、麦克风与摄像头内容、触摸坐标、崩溃日志。

设备标识本身（例如系统安装标识）只写在本机凭据里用于本地校验，不作为原始值上传。

### 3. 版本检查

激活链路中会并行做一次版本检查。有新版本时会在客户端提示。

更新流程是**打开浏览器**：应用用系统 `ACTION_VIEW` 打开服务端给的下载链接，交给系统浏览器处理。应用**不下载 APK、不申请安装权限、不做静默安装**。

更新提示窗口的默认文案：

- 标题：发现新版本
- 正文：本次更新包含功能优化与问题修复。
- 大小行：文件大小：`<大小>`
- 按钮：立即下载 / 稍后更新（强制更新时是「退出应用」）

录制过程中如果检测到新版本，会显示一张**不会被录进画面**的提示卡：标题「检测到新版本」，正文「建议您进入小白录制app进行更新」，底部固定小字「此提示不会被录制」。

## 公告不是给你看的

应用有完整的公告数据模型与拉取流程，但**公告内容在界面上完全不展示**。

它唯一的用途是：从公告正文里提取 `SIGNATURE_SHA256=<64 位十六进制>` 这一行，作为**本地 APK 签名校验的基准摘要**——也就是远程下发"当前 APK 应该是什么签名"，用来发现二次打包。

特权进程会**再解析一次**同样的文本，这样应用侧无法伪造判定结果。如果公告里有多个不一致的摘要、或格式不对，会报错「公告缺少有效的 SIGNATURE_SHA256，或存在冲突摘要」。

## 完整性校验与静默退出

当安装包的签名与公告中声明的摘要不符时，应用会**无提示地结束自身进程**——没有弹窗、没有上报、没有通知。

对用户来说表现为：应用突然退出，没有任何解释。如果遇到这种情况，通常意味着安装包被修改过（重新签名、二次打包）。

## 权限与处理时机

所有权限都在你使用对应功能时才申请，不会在同意隐私政策的瞬间集中申请。逐项说明见[权限说明](/guide/permissions)。

## 第三方组件

| 组件 | 用途 | 是否联网 |
| --- | --- | --- |
| FFmpeg / FFmpegKit | 音视频处理 | 否（本机运行） |
| AndroidX 与 Jetpack Compose | 界面与系统能力基础库 | 否 |
| Miuix | 界面组件库（毛玻璃与液态玻璃效果） | 否 |
| ConfettiKit（Apache-2.0） | 首次引导结束时的彩带动画 | 否 |
| Bouncy Castle | 加密算法（X25519 / Ed25519 / ChaCha20-Poly1305 等） | 否 |
| OkHttp | 应用侧的 HTTPS 通信 | 是（见上文） |

以上组件都不会把数据传输给它们的作者。应用**没有**接入任何第三方统计、广告、推送、社交、支付或崩溃上报服务。

## 与站内隐私政策的差异

站内[隐私政策](/privacy)是面向**精简版**的文本，其中这两句不适用于完整版：

> 没有激活校验、没有版本检查、没有统计上报。

> 唯一的联网行为是第五条的运行库下载，该下载不包含你的任何文件。

完整版（Root / Shizuku 采集 + 高级版激活）额外有激活校验、心跳与版本检查，并且如上一节所述，其中一部分走在明文 HTTP 上。如果你要发布或更新隐私政策，需要按本页内容补充这几项。
