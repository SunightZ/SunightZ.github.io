# 外部启动

主页「外部启动」区块提供两个入口，让第三方自动化或手势应用（例如 GestureEVO）静默调用录制行为。

<div class="sr-note">
<strong>高级版功能。</strong>未激活时调用这个入口会提示「外部启动录制需要激活高级版」并立即退出，不会启动录制或悬浮球。
</div>

## 两个入口

主页上以可复制的代码块展示：

**Activity 名称**

```
com.sunight.screenrecorder.ExternalCommandActivity
```

**Shell 命令**

```
am start -n com.sunight.screenrecorder/.ExternalCommandActivity
```

点代码块即复制，提示「已复制」。

## 行为

这个 Activity 是**无界面桥接**：启动后立即结束，不打开录制主页。它会读取应用中已保存的录制配置，并**跟随「磁贴启动悬浮菜单」开关**的行为设置。

### 三个命令

| 动作 | 常量 | 效果 |
| --- | --- | --- |
| 开始录制 | `com.sunight.screenrecorder.action.SHELL_START` | 直接开始录制 |
| 启动悬浮菜单 | `com.sunight.screenrecorder.action.SHELL_FLOATING` | 唤起悬浮球 |
| 停止录制 | `com.sunight.screenrecorder.action.SHELL_STOP` | 停止当前录制 |

如果调用时**不指定动作**（或指定的是 `MAIN` / `VIEW`），则按「磁贴启动悬浮菜单」开关决定：开启则启动悬浮菜单，关闭则直接开始录制。

### 开始录制的前提

外部启动的「开始录制」比正常路径更严格，因为它没有界面来弹权限说明：

| 检查 | 失败提示 |
| --- | --- |
| 没有正在进行的录制 | 已有录制任务正在进行 |
| 录制方式必须是 Shizuku 或 Root | 普通模式不能通过 Shell 静默启动 |
| Shizuku 已启动并授权 | 请先启动并授权 Shizuku |
| Root 已授权（实际执行 `id` 验证） | 请先在管理器中授予 Root 权限 |
| 已保存录制配置 | 请先在应用中保存录制参数 |

**系统录屏（MediaProjection）模式不能通过这个入口静默启动**——它每次都需要你确认系统授权弹窗，静默启动没有意义。

其他失败提示：

| 情况 | 提示 |
| --- | --- |
| 启动悬浮菜单但没有悬浮窗权限 | 请先授予悬浮窗权限 |
| 命令本身出错 | 命令启动失败：… |
| 未知动作 | 未知命令 |

## 激活校验

调用这个入口会依次检查：

1. 应用签名是否为公告中声明的那个
2. 是否存在有效的高级版凭据

凭据校验会在本机完成，包括比对安装标识与凭据中的设备标识。任何一步失败都会提示「外部启动录制需要激活高级版」并结束。

## 安全考虑

这个入口是 `exported` 的（第三方应用需要能调用它），但：

- 它**不检查是谁发起的**，而是检查**本应用是否已激活高级版**。也就是说，能调用它的前提是你的设备上已经激活并配置好了 Shizuku / Root 录制。
- 它**不会**把录制文件返回给调用方。
- 系统录屏模式无法通过它静默启动——那条路径始终需要你的系统授权确认。
