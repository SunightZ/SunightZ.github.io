# 运行库

视频工具需要一套体积较大的 FFmpeg 原生运行库。应用**不把它塞进安装包**，而是在你首次使用视频工具时下载。

<div class="sr-note">
<strong>不使用视频工具箱，应用就不会联网。</strong>这是应用唯一的联网行为（另一处是完整版的卡密激活校验）。
</div>

## 下载与校验

| 项目 | 值 |
| --- | --- |
| 版本 | FFmpegKit 8.1.9（full 构建） |
| 架构 | arm64-v8a |
| 界面提示的下载量 | 约 8 MB |
| 归档上限 | 80 MB |
| 安装位置 | 应用私有目录 `files/ffmpeg/8.1.9/arm64-v8a` |

下载地址有两条，主地址不通时自动改用备用地址：

1. 经由 GitHub 代理的地址（正常路径）
2. GitHub 原始地址（代理故障时保底）

下载完成后会：

1. 逐个文件计算 SHA-256，与内置的摘要比对——**校验不通过的库不会被加载**；
2. 确认十个库文件一个不少；
3. 把安装目录整体重命名到位，并写入完成标记；
4. **把库文件设为只读**，然后才加载。

### 为什么要设成只读

Android 17（API 37）把「更安全的动态代码加载」扩展到了原生代码：交给系统按路径加载的文件，在加载期间不能是可写的——因为可写的代码文件可以在任何检查之后被替换掉。

下载来的文件默认是可写的，所以应用会在**每次安装后**以及**每次加载前**都检查并加固。如果某个安装目录无法置为只读，应用会把它整个删掉、回到「未下载」状态，而不是留下一个永远加载不了的目录——后者会让工具永久损坏且没有恢复路径。

### 为什么加载顺序有讲究

原生库之间存在依赖：`libffmpegkit.so` 依赖 avutil、avcodec、avformat、avfilter、avdevice、swscale、swresample 和 libc++_shared。

打包在 APK 里时链接器会自动解析这些依赖，但 FFmpegKit 只在很老的系统上自己加载它们。从下载目录加载时它们并不在进程里，链接就会失败——而且 FFmpegKit 会把这个失败包装成一条关于"版本号"的报错，让人看不出真正的原因。

所以应用会**按依赖顺序显式预加载**：libc++_shared → avutil → swresample → swscale → avcodec → avformat → avfilter → avdevice，最后才让 FFmpegKit 加载自己。

## 界面上的四种状态

工具页的「运行库」区块只在尚未就绪时出现：

| 状态 | 标题 | 摘要 |
| --- | --- | --- |
| 未下载 | 下载 FFmpeg 运行库 | 视频工具需要额外下载约 8 MB 的运行库 |
| 下载中 | 正在下载 FFmpeg 运行库 | 下载进度 N% / 正在连接下载服务器… |
| 就绪 | FFmpeg 运行库已就绪 | 视频工具可以使用 |
| 失败 | 重新下载 FFmpeg 运行库 | `错误信息`，点击重试 |

## 失败时可能看到的提示

| 提示 | 含义 |
| --- | --- |
| 下载服务器返回 HTTP `N` | 服务器返回了非成功状态码 |
| 下载文件过大 | 超出 80 MB 上限 |
| 下载文件为空 | 拿到 0 字节 |
| FFmpeg 文件校验失败：`文件名` | SHA-256 不匹配 |
| FFmpeg 下载包缺少库文件 | 归档里少了某个库 |
| 无法安装 FFmpeg 文件 | 重命名到位失败 |
| FFmpeg 安装校验失败 | 安装后复检不通过 |
| FFmpeg 运行库无法置为只读 | Android 17 起无法按路径加载 |
| 运行库缺少 `文件名` | 加载时找不到某个库 |
| 运行库仍可写，Android 17 起不能按路径加载：`文件名` | 加固失败 |

## 为什么选这个构建

用的是 `ffmpeg-kit-full` 8.1.9 —— Arthenica 停止维护后由社区接手的版本，针对较新的 SDK 构建。

这不是随意选的：RxFFmpeg 发布的 4.9.0 二进制（FFmpeg 4.0、NDK r10e、`--disable-asm`）在 Android 16 上会**在完成工作之后**崩溃，而且这个问题从纯原生测试程序里就能复现，没有 Java 参与——也就是说应用侧改什么都没用。
