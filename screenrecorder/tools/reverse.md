# 视频倒放

画面与声音同时倒序，输出 MP4。文件时长不变。

## 为什么要分段

倒放需要把整段视频**读进内存再反向输出**——这是 FFmpeg `reverse` 滤镜的工作方式。一段几分钟的 4K 视频直接倒放会耗尽内存。

所以应用会先按内存预算把视频切成若干小段，逐段倒放，再按相反顺序合并起来。

## 切片规则

切片的长度按分辨率与帧率算，目标是把每一段控制在约 64 MB 的内存占用内：

- 单段时长会被限制在 **1 毫秒 ～ 1 秒**之间
- 分段数上限 **20,000** 段

这个设计意味着：**分辨率越高、帧率越高，段就越短、段数越多**。

## 会被拒绝的情况

以下情况应用会直接拒绝处理并说明原因，而不是冒险耗尽内存：

| 情况 | 提示 |
| --- | --- |
| 读不到时长 | 无法读取视频时长，不能安全地倒放 |
| 分辨率过高或读不到 | 视频分辨率过高或无法读取，倒放可能耗尽内存 |
| 尺寸异常 | 无法安全处理此视频尺寸，请先缩小分辨率 |
| 读不到有效帧率 | 无法读取有效帧率，不能安全地倒放 |
| 分段数超过 2 万 | 视频过长，倒放需要过多临时分段 |

遇到这些提示时，先用[视频压缩](/tools/compress)把分辨率降下来，再倒放。

## 处理过程

1. **分段倒放**（占进度 0～90%）：每段用 `reverse` 倒放画面、`areverse` 倒放声音，并重置时间戳。中间结果用 MKV 暂存。
   - 有音轨时每段的音频存为 PCM，避免每段都做一次 AAC 编码造成累积损失。
   - 分段之间最多并行 2 个；低内存设备或短边超过 1080 时只用 1 个。
2. **合并**（占进度 90～99%）：按相反顺序拼接所有分段，视频直接复制，音频统一重编为 AAC 192 kbps，并加快速起播标记。

## 编码参数

| 项目 | 值 |
| --- | --- |
| 视频编码器 | H.264（硬件优先，软件回退） |
| 码率 | 按**源视频**短边取画质档位 |
| 音频 | 分段用 PCM，合并时重编为 AAC 192 kbps |
| 输出格式 | MP4（带快速起播标记） |
