# 视频工具箱

录完不用换 App。工具箱把常用的 FFmpeg 任务做成点击即用，**同一时间只跑一个任务**，结果保存到与录制相同的保存位置，**原文件不动**。

## 八个工具

按工具页上的实际顺序：

| 工具 | 副标题 | 做什么 |
| --- | --- | --- |
| [视频格式转换](/tools/convert) | 转为 GIF 动图，或 MP4 / MKV / MOV / WebM 等容器 | 换容器或换编码 |
| [提取音频](/tools/extract) | 从视频中提取 MP3 / M4A / WAV / FLAC / OGG | 只取音轨 |
| [视频压缩](/tools/compress) | 按目标体积或码率重新编码，适合分享 | 让文件更小 |
| [视频超分](/tools/upscale) | scale 滤镜放大画面并重新编码 | 2× / 3× / 4× 放大 |
| [旋转与镜像](/tools/rotate) | 修正录屏方向，支持 90°/180° 与镜像 | 救回方向录错的视频 |
| [视频倒放](/tools/reverse) | 画面与声音同时倒序，输出 MP4 | 倒放 |
| [音量调整](/tools/volume) | 手动增益或响度标准化 | 改已有文件的音量 |
| [抖音投稿帧数优化](/tools/douyin) | 仅限 60 FPS 及以上：处理后从电脑端创作者中心投稿，移动端不再被压到 30 FPS | 保留 60 FPS |

## 怎么用

1. 点工具页上的某一项（第一次用会先让你[下载运行库](/tools/runtime)）。
2. 通过系统文件选择器选一个视频。**选完立刻读取文件信息**——时长、分辨率、帧率、音轨编码都会显示在对话框上。
3. 在对话框里调参数（每个工具的选项见各自页面）。底部固定显示一行 `输出：<格式>`。
4. 点「开始处理」。
5. 处理中会显示进度百分比、当前速度倍率与已处理时长，随时可以点「取消转换」。

<div class="sr-note">
<strong>同一时间只跑一个任务。</strong>有任务在跑时，其他工具都是灰的。任务在前台服务里执行，退出界面可以，但别强制结束进程。
</div>

## 公共管线

八个工具共用一套执行与保存流程，几个约定对所有工具成立：

### 编码器选择

应用只用构建里实际存在的编码器，按「硬件优先、软件回退」尝试：

| 目标 | 候选编码器 |
| --- | --- |
| H.264 | `h264_mediacodec` → `libopenh264` |
| H.265 | `hevc_mediacodec` → `libkvazaar` |
| VP9（WebM） | `libvpx-vp9` |

构建里**没有** `libx264` / `libx265` / `libfdk_aac`，代码也刻意不写这些名字。如果某个目标一个可用编码器都没有，会明确报错「当前 FFmpeg 构建缺少可用的视频编码器：…」，而不是产出一个坏文件。

### 音轨是复制还是重编码

这是各工具差异最大的一处，规则如下：

| 情况 | 处理 |
| --- | --- |
| 音轨编码能装进目标容器 | **直接复制**（`-c:a copy`），不写码率 |
| 目标编码器是无损的（PCM / FLAC） | 重编码，不写码率 |
| 其他 | 按源音轨码率重编码；探测不到源码率时用 192 kbps |

源码率会被夹在 64～320 kbps 之间。GIF 目标不含音轨。

按工具看：

| 工具 | 音轨处理 |
| --- | --- |
| 格式转换 | 能装就复制，否则按源码率重编 |
| 提取音频 | 能装就复制（此时是**无损提取**，例如 AAC 源 → M4A） |
| 视频压缩 | 恒重编为 AAC 128 kbps |
| 视频超分 | 恒重编为 AAC 192 kbps |
| 旋转与镜像 | 恒重编为 AAC 192 kbps |
| 视频倒放 | 分段用 PCM，合并时重编为 AAC 192 kbps |
| 音量调整 | 恒重编（本来就是改音频） |
| 抖音投稿帧数优化 | **直接复制**，不重编码 |

### 输出命名

`<原文件名>_<任务名>_<yyyyMMdd_HHmmss>.<扩展名>`

原文件名会去掉扩展名，并把中文、字母、数字、空格、下划线、点、连字符之外的字符替换成下划线，最多保留 80 个字符；为空时用 `video`。

### 输出保存

先写到应用缓存里的临时文件，成功后再发布到正式位置，三级回退：

1. 你在「保存位置」里选的文件夹
2. 系统媒体库（按类型：视频 → `Movies/ScreenRecorder`，音频 → `Music/ScreenRecorder`，图片 → `Pictures/ScreenRecorder`）
3. 应用自己的目录

成功提示形如「已保存：Movies/ScreenRecorder/xxx.mp4」。三级都失败时会说明每级的原因，并给出应用目录里的绝对路径。

### 线程预算

按输出分辨率与设备内存决定并行度：

| 情况 | 线程数 |
| --- | --- |
| 输出短边 > 2160 | 1 |
| 低内存设备，或输出短边不在 1～1080 之间 | 2 |
| 其他 | min(4, CPU 核心数) |

### 进度与取消

进度对话框标题「正在转换」，副标题是「目标格式 · 输出文件名」，进度文本显示百分比，处理中会追加速度倍率（如 `1.35x`）与已处理时长。点「取消转换」后进入「正在取消」状态，正文「正在停止转码，请稍候…」。

### 结果

| 标题 | 什么时候 |
| --- | --- |
| 转换完成 | 成功 |
| 保存失败 | 转码成功但写文件失败 |
| 转换失败 | 转码本身失败 |

按钮有「打开」（用系统播放器打开结果）、「分享」（仅有可用地址时）与「确定」。打开失败提示「没有可打开该格式的应用」。

## 常见失败提示

| 提示 | 含义 |
| --- | --- |
| 请先在工具页面下载 FFmpeg 运行库 | 运行库没装好 |
| 无法读取所选文件 | 选中的文件打不开 |
| 临时空间不足：读取该文件约需 N MB，当前可用 M MB | 缓存空间不够 |
| FFmpeg 报告成功但没有写出任何数据，请换一种输出格式或换一个源文件 | 编码器静默失败 |
| 转码已完成，但保存失败：… | 见上面的三级回退 |
| FFmpeg 退出码 N | 底层错误 |
| 转换已取消 | 你点了取消 |
