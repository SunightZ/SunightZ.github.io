# 视频超分

用 `scale` 滤镜放大画面并重新编码。

<div class="sr-note">
<strong>先说清楚：插值不会凭空增加细节。</strong>超分只是把画面放大并用 lanczos 插值填补像素，模糊的细节不会回来。它的实际用途是让低分辨率录制在大屏上不那么糊，或者统一不同素材的分辨率。
</div>

## 放大倍数

滑块范围 **1.0× ～ 上限**，步进 0.1×。上限由 8K 长边换算：

```
上限 = min(7680 ÷ 源长边, 8.0)
```

举几个例子：

| 源分辨率 | 上限 |
| --- | --- |
| 1080p（1080×1920） | 4.0× |
| 4K（2160×3840） | 2.0× |
| 较小素材 | 8.0× |

对话框上会实时显示换算结果：

> 输出分辨率 `1920 × 1080` → `3840 × 2160`

以及一段固定说明：

> 上限 `N.N`× 由 8K 长边（7680）换算得出。scale 滤镜以 lanczos 插值放大，画面本身不会凭空多出细节；倍数越高编码负担越大，输出尺寸还需设备编码器支持。

## 编码参数

| 项目 | 值 |
| --- | --- |
| 视频编码器 | H.264（硬件优先，软件回退） |
| 码率 | 按**放大后**的短边取档位（见下表） |
| 音频 | 恒定重编为 AAC 192 kbps |
| 输出格式 | MP4（带快速起播标记） |

放大后的码率档位：

| 放大后短边 | 码率 |
| --- | --- |
| ≤ 720 | 8 Mbps |
| ≤ 1080 | 12 Mbps |
| ≤ 1440 | 24 Mbps |
| ≤ 2160 | 60 Mbps |
| > 2160 | 100 Mbps |

尺寸会强制为偶数——4:2:0 的硬件编码器不接受奇数边长。

**1.0× 是一个特殊值**：不套任何滤镜，只做一次纯重编码。想换编码格式或调码率又不想动画面时可以用它。

## 什么时候值得用

| 场景 | 建议 |
| --- | --- |
| 低分辨率录屏要在电视上放 | 2× 通常够 |
| 老素材要和新素材混剪，分辨率不一致 | 放大到统一尺寸 |
| 想从 1080p 得到"4K 文件" | 可以，但不会有 4K 细节——只是文件更大 |
| 想救糊掉的视频 | **不行**，换别的手段 |

## 输出尺寸要设备支持

放大后的分辨率还需要设备编码器支持。例如 1080p 素材放大 4× 得到 4320×7680，很多设备的编码器不接受这个尺寸，会报错。遇到时降低倍数再试。
