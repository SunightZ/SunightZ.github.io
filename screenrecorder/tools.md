# 视频工具箱

录完不用换 App。工具箱把常用的 FFmpeg 任务做成点击即用，**同一时间只跑一个任务**，结果保存到与录制相同的保存位置，**原文件不动**。

第一次使用时会下载 FFmpeg 原生运行库（应用不把它塞进安装包），下载后按内置的 SHA-256 逐个文件校验，校验不通过的库不会被加载。**不使用视频工具箱，应用就不会联网。**

## 七个工具

| 工具 | 做什么 | 要点 |
| --- | --- | --- |
| 视频格式转换 | 转成 MP4 / MKV / MOV / GIF 等 | 音轨能装进目标容器时直接复制（不重新编码）；否则按源音轨码率重编，探测不到时用 192 kbps。GIF 不含音轨 |
| 提取音频 | 从视频里取出音轨 | 目标容器兼容时是无损提取（例如 AAC 源 → M4A） |
| 视频压缩 | 降低码率/分辨率，文件更小 | 适合分享、上传有体积限制时 |
| 旋转与镜像 | 旋转 90°/180°/270°、水平或垂直镜像 | 画面方向录错了用它救 |
| 音量调整 | 提高或降低整段音量 | 与录制时的增益是两件事：这里改的是已有文件 |
| 视频超分 | 2× / 3× / 4× 放大 | 用 `scale` 滤镜 + lanczos 插值重编码，码率按放大后短边取档位。插值不会凭空增加细节，输出尺寸还要设备编码器支持 |
| 抖音投稿帧数优化 | 让 60 FPS 视频在移动端投稿后不被压到 30 FPS | 时间戳放大 2 倍（`-itsscale 2`），视频与音频**直接复制、不重编码**，输出时长变为原来的 2 倍 |

## 抖音投稿帧数优化为什么这么处理

移动端直接上传会被平台压到 30 FPS；未经处理的文件即使从电脑端投稿也一样。这个工具把时间戳整体放大 2 倍，平台按 30 FPS 解码后正好还原成 60 FPS——所以：

- 输出文件时长是原来的 2 倍，属正常现象；
- 处理后的文件请**从电脑端创作者中心投稿**，移动端才能保留 60 FPS；
- 点击工具时会先显示介绍弹窗：用两块自绘手机屏幕分别以 30 FPS 与 60 FPS 播放同一段小球动画，直观看出差异；
- 选好视频后会立即读取原始帧率，低于 60 FPS（或读不出帧率）时拒绝处理，「开始处理」不可点击。

## 常见问题

- **处理中途可以退出应用吗？** 建议不要，任务在前台服务里跑，退出界面可以但别强制结束进程。
- **为什么转换后文件反而更大？** 目标格式或码率设置比源更高，换更高的压缩档位或降低分辨率。
- **超分能救糊视频吗？** 不能。它只是放大与插值，模糊的细节不会回来。
