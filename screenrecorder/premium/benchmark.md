# 实测数据

Root / Shizuku 直接建立系统级采集通道，省掉应用层转发与跨进程等待；**负载越高、帧率越高，差距越明显**。

<div class="sr-note">
<strong>数值为同一台设备上的对比结果，会随设备与负载变化。</strong>测试条件是同一台设备、播同一段内容、使用完全相同参数（原画分辨率 @ 屏幕最高刷新率）。
</div>

## 三张对比图

权益页上展示的三张图（数据取自一次发布前的实测）：

### 单帧耗时累积分布

曲线越靠左上越好。横轴是单帧耗时（毫秒），图上标有一条 8.3 ms 的预算线——那是 120 FPS 下每帧可用的时间。

累积分布越靠左上，说明有越多比例的帧在预算内完成。

### 每帧 CPU 耗时

按进程拆分，越低越省电。这一项直接反映三种采集方式在编码链路上花了多少 CPU 时间。

### 健康度对比

三个指标放在一起看：超预算帧比例、掉帧比例、每帧 CPU 耗时。

## 数值

| 指标 | 系统录制 | Shizuku | Root |
| --- | --- | --- | --- |
| 每帧 CPU 耗时 | 8.89 ms | 6.40 ms | 6.20 ms |
| 超预算帧 | 1.87% | 1.27% | 1.25% |
| 掉帧 | 1.70% | 1.45% | 1.24% |

### 怎么读这组数

- **每帧 CPU 耗时从 8.89 ms 降到 6.40 ms**：8.3 ms 是 120 FPS 的每帧预算，系统录制平均已经超了，Shizuku / Root 还有余量。这就是"能不能稳住 120 FPS"的分界。
- **超预算帧从 1.87% 降到 1.27%**：每一百帧里，超出预算的帧少了三分之一。
- **掉帧从 1.70% 降到 1.24%**：观众能感知到的卡顿减少。
- **Shizuku 与 Root 差距不大**：两者的采集链路本质相同，Root 略优（省掉 Shizuku 的守护进程通信）。

<div class="sr-note">
<strong>这组数据来自一次发布前的实测，不是每台设备的运行时测量。</strong>你的设备上差距可能更大也可能更小——低负载场景（静态画面、低帧率）下三者几乎没有区别，差距主要体现在高帧率游戏录制。
</div>

## 适合什么场景

| 场景 | 建议 |
| --- | --- |
| 录静态画面、看文档 | 系统录屏就够，三种方式没差别 |
| 录 60 FPS 游戏 | Shizuku 或 Root，帧时间更稳 |
| 录 120 FPS 游戏 | Root 最稳 |
| 长时间录制 | Root（录制进程独立，不依赖应用存活） |
| 不想每次点系统弹窗 | Shizuku 或 Root |
