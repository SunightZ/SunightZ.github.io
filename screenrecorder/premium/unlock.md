# 解锁与激活

## 入口

主页右上角菜单里的「解锁高级版」——**只在未激活时出现**。

另外，当你选择 Root / Shizuku 模式却没有有效凭据时，会自动弹出解锁提示。

## 解锁对话框

标题「解锁高级版」，摘要「开发不易，感谢支持ヾ(≧▽≦*)o」。

内容：

- 一个输入框，标签「请输入卡密」
- 两个链接：「查看全部高级版权益」与「没有卡密？前往商城购买」
- 按钮「取消」与「激活」（校验中变成「验证中…」）

卡密为空时点「激活」会提示「请输入卡密」。

「查看全部高级版权益」打开权益页，「没有卡密？前往商城购买」打开商城页面；没有可用的浏览器时提示「没有可打开商城的浏览器」。

## 模式拦截对话框

当你选了 Root 或 Shizuku 模式但还没激活时，会看到另一个对话框：

- 标题「该模式需解锁高级版」
- 内容：三张实测对比图（见[实测数据](/premium/benchmark)）
- 按钮「继续体验」与「前往购买」
- 提示文字「未激活：Root / Shizuku 可体验 1 分钟」

从控制中心磁贴触发时，这个对话框的标题是「解锁专业录制能力」，摘要「Root 与 Shizuku 走系统级采集链路，绕开应用层转发与跨进程调度」。

## 激活时发生什么

点「激活」后，应用会与授权服务器建立会话并验证卡密。校验通过后会：

1. 在本机保存一份**激活凭据**
2. 把卡密绑定到本机设备

### 凭据里有什么

凭据在本机生成并签名，内容包含：

| 字段 | 说明 |
| --- | --- |
| 版本号 | 凭据格式版本 |
| 包名 | 防止凭据被移植到其他应用 |
| 设备标识 | 防止凭据被复制到其他设备 |
| 授权类型 | 当前为永久授权 |
| 唯一标识 | 本次激活的随机标识 |
| 签名摘要 | 当前安装包的签名摘要 |

凭据使用 Android Keystore 中的密钥做 HMAC 认证。Keystore 能防止普通应用读取密钥，也能阻止简单地把授权文件复制到其他安装环境。

<div class="sr-note">
<strong>这是本机签名，不是服务器签名。</strong>凭据由客户端在本机生成，其"必须在服务器验证成功之后调用"的限制只存在于调用流程与注释里。这意味着能修改安装包或注入进程的攻击者可以跳过联网激活分支直接本地签发。对于防破解目标，这是一个已知的弱点；对普通用户没有影响。
</div>

## 设备绑定

卡密会绑定到**验证它的那个设备**。

这里有一个细节：应用进程与 Root / Shizuku 录制进程算出的设备标识并不相同——录制进程是 root，能读到的属性与系统节点比应用多。如果不处理，同一台手机在服务器眼里会成为两台设备，刚在应用里激活完的卡密会被判成「该卡密已绑定其它设备」。

处理方式是让录制进程出示**客户端自己的设备标识**，这样两条链路出示的是同一个设备。永久链路在这个标识被拒时，还会用本机推导的标识再试一次。

## 激活之后

- Root / Shizuku 录制不再有 1 分钟限制
- 触摸可视化不再有 1 分钟限制
- 屏幕标注可用
- 外部 Activity 静默启动可用

## 没有卡密时

- **先试一下**：Root / Shizuku 与触摸可视化都有 1 分钟试用，见[试用与限制](/premium/trial)。
- **购买**：从解锁对话框里的「没有卡密？前往商城购买」进入。
