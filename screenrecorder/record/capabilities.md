# 设备编码器能力

页面上的参数上限**不等于设备保证支持**。真正可用的分辨率、帧率、码率由设备的硬件编码器决定。这一页说明应用怎么问编码器、参数超限时会报什么错、首次启动怎么收敛默认值。

## 应用怎么问编码器

启动录制前，应用会列出设备上所有**支持 Surface 输入的视频编码器**（排除别名），按你选的「硬件编码 / 软件编码」筛选，然后逐个试你要用的那一整套参数。

判定的是**完整组合**，不是单项上限。也就是说 `1920×1080` 单独可行、`60 FPS` 单独可行，不代表 `1920×1080 @ 60 FPS @ 12 Mbps` 这一套一定可行——很多编码器只在某些尺寸下才开放高帧率。

## 首次启动时收敛默认值

安装后第一次打开应用时，会按「尺寸 × 帧率」从高到低试一遍，把默认参数收敛到受支持的最高一档：

- 先降尺寸（原画 → 8K → 4K → 2K → 1080p → 720p → 480p → 360p）
- 再降帧率（当前值 → 60 → 30 → 24 → 15）
- 最后把码率夹进编码器报告的范围

收敛后会提示：

> 已按设备编码能力调整录制参数：`{宽}×`{高} · `{帧率}` FPS

这一步**只在首次安装且不是状态恢复时执行一次**，之后你的手动设置不会被覆盖。如果全部组合都试不通，则不改动参数（保持原样，让开始录制时明确报错）。

<div class="sr-note">
<strong>自动降档不会升档。</strong>尺寸阶梯会先过滤掉比屏幕原画更高的档位，所以 1080×2400 的屏幕不会被"降"成 3456×7680。而分辨率滑块在 8K 包络内是允许手动放大到 100% 以上的（超分录制）。
</div>

## 超限时的提示

按优先级从具体到笼统，应用会给出最贴近原因的那一条：

| 情况 | 提示 |
| --- | --- |
| 一个编码器都没有（硬件） | 没有找到可用的 H.265/H.264 硬件编码器，可把「编码选择」改为软件编码再试 |
| 一个编码器都没有（软件） | 没有找到可用的 H.265/H.264 软件编码器 |
| 只有 CBR 不被接受 | 该编码器不支持当前码率下的固定码率（CBR），请把码率模式改回可变码率（VBR） |
| 帧率超上限 | `{宽}×{高}` 在该编码器下的帧率上限是 `{上限}` FPS，请把帧率降到 `{上限}` 或更低 |
| 其他组合问题 | 编码器不接受 `{宽}×{高}` · `{帧率}` FPS · `{码率}` Mbps 这一整套参数，请降低分辨率、帧率或码率 |

如果整套参数在启动时仍然不通，兜底提示是：

> 当前参数组合不受支持：`{宽}×{高}` · `{帧率}` FPS · `{码率}` Mbps。请按编码器能力修改参数。

## 界面上的标红规则

「参数预览」与输入框会标出是**哪一项**出了问题：

- 如果某一项（宽、高、帧率、码率）单独就超出范围，标红那一项。
- 如果四项**各自都通过、但整套组合不通过**，应用会强制标红**帧率**——这是最常见、也最容易调整的整体限制项。

输入框上方的括号里会显示编码器报告的范围，形如 `1280–4096`；多个编码器之间用 ` / ` 连接；没有交集时显示「无可用范围」，读取异常时显示「无法读取」。

## 查看完整能力清单

主页「画面设置」里有「设备编码器能力」入口，点开是一个可滚动的对话框，逐个编码器列出：

- 名称与类型（软件编码 / 硬件编码）
- 支持的宽度范围、高度范围
- 宽、高分别必须是几的倍数
- 码率范围（Mbps）
- 当前尺寸下可用的帧率范围（尺寸未填时提示「填写宽高后显示该尺寸可用帧率」；该尺寸不支持时明确写「当前尺寸 `{宽}×{高}` 不支持」）
- 当前参数组合是否支持，以及支持哪种码率模式

对话框结尾固定一句话：

> 以上为系统报告的能力；宽、高、帧率上限不能任意组合，实际运行仍受设备负载影响。

## 动态帧率与动态码率怎么配合

这两个开关不改变"能不能录"，只改变"录的时候跑多快"。它们共用同一套负载判断，**帧率优先让路**：

| 负载 | 动作 |
| --- | --- |
| ≤ 55% | 不动 |
| ≥ 95% | 帧率降到下限 |
| ≥ 130% | 码率也降到下限 |

- 帧率下限：`max(15, 目标帧率 ÷ 3)`
- 码率下限：`max(2 Mbps, 目标码率 ÷ 4)`
- 调整步长：帧率上升 4 / 下降 10；码率上升 10% / 下降 25%
- 3% 死区，避免在临界点反复抖动

界面上这两个开关都标注了「算法测试中，可能不稳定」——如果录制出现明显的帧率波动，先关掉它们。

## 常见误解

**「我的手机是 120 Hz，所以能录 120 FPS」**
屏幕刷新率只决定帧率的**上限**。能不能真的以 120 FPS 编码，取决于编码器在你要的分辨率下是否支持——很多设备只在 1080p 及以下开放高帧率。

**「静态画面时帧数不对」**
帧率是目标/上限，静态画面不保证持续生成这么多帧。镜像显示只在画面变化时出帧，所以录一段不动的画面，文件里可能只有很少的帧——这是正常的。

**「模拟器上能跑，真机不行」**
模拟器上的软件编码器经常"自称支持"某些模式，实际会失败。判断方式是拿真机试。
