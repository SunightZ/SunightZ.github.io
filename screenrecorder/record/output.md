# 保存、暂停与恢复

## 保存位置

| 类型 | 默认位置 |
| --- | --- |
| 视频 | `Movies/ScreenRecorder` |
| 音频（提取音频工具） | `Music/ScreenRecorder` |
| 图片（标注截图） | `Pictures/ScreenRecorder` |
| 暂存目录（应用私有） | `<外部应用目录>/ScreenRecorder` |

- **默认**：`Movies/ScreenRecorder`，录制结束会自动登记到系统相册。
- **自定义**：在主页「保存位置」里通过系统文件选择器挑一个文件夹，授权会持久保存；点「使用默认」回到 `Movies/ScreenRecorder`。
- 自定义文件夹**是否显示在系统相册里取决于系统索引**——有些第三方的文件管理器目录不会被媒体库扫描，但文件确实在那里。
- 视频工具箱的输出与录制使用同一个保存位置，原文件不动。

### 文件名

- 录制：`录屏_yyyyMMdd_HHmmss.mp4`
- 标注截图：`标注_<毫秒时间戳>.png`
- 工具输出：`<原名>_<任务名>_<yyyyMMdd_HHmmss>.<扩展名>`

### 同名怎么办

录制进程以独占方式创建文件，**已有文件和最终路径上的符号链接一律拒绝**，不会覆盖。如果同名文件已存在，会改用 `名字 (1).mp4`、`名字 (2).mp4`……并在保存结果里回报真正使用的路径。

## 云盘等没有文件系统路径的位置

如果你选的文件夹背后没有真实文件系统路径（例如某个云盘提供方），录制进程无法直接写进去。这时应用会把录制**暂存在自己的外部目录**里，等录制结束（或下次进入应用）再搬进你选的目录。

暂存的文件是完整的、就在磁盘上，所以即使应用中途被杀也不会丢——只是要等下一次启动才会出现在你选的文件夹里。

## 停止与保存

停止录制后，应用需要先合并音视频再写入文件，请等待「保存完成」的提示。

保存成功会显示路径，形如：

> 已保存：Movies/ScreenRecorder/录屏_20260101_120000.mp4

<div class="sr-note">
<strong>强制结束进程或设备断电不能保证 MP4 完整。</strong>视频封装器只在停止时才写文件索引，这是格式本身的限制。保存失败时临时文件会保留在应用私有目录的 recordings 里，重新打开应用时有机会自动补登记。
</div>

### 保存失败时

保存失败会提示「保存失败：…」，并给出临时文件路径。文件通常还在，可以尝试：

1. 重新打开应用，让它自动补登记。
2. 用文件管理器到应用私有目录的 `recordings` 里找。

## 暂停与继续

录制中可以暂停：

| 入口 | 操作 |
| --- | --- |
| 通知栏 | 「暂停」/「继续」动作 |
| 悬浮球菜单 | 「暂停」/「继续」 |
| 悬浮工具栏 | 录制按钮 |
| 应用内 | 录制按钮 |

暂停时通知标题变成「录制已暂停」，悬浮球显示 `▶`。暂停期间不计入时长，恢复后继续写入同一个文件。

## 息屏行为

「控制与安全」里的「息屏后暂停录制」开关（默认关闭）：

> 息屏后录制暂停，亮屏后自动恢复。若息屏超过6分钟，将自动结束录制。

开启后，锁屏会暂停录制而不是继续消耗电量；超过 6 分钟则结束并保存。

## 长时间录制的稳定性

「保持录制稳定」的电池优化豁免建议开启。未开启时主页「参数预览」里会显示一条可点击的提示「录制可能被系统中断」+「开启豁免」。

## 启动时的两段自愈

应用启动时会在后台检查两类遗留文件：

### 移入暂存的录制

把暂存在应用目录里的录制搬进你选的文件夹。判定条件是文件大于 1 KB 且**最近 5 秒内没有被修改**（还在写入的文件会被跳过）。完成后提示：

> 移入 N 段暂存的录制

### 补登记漏掉的录制

把磁盘上有、但系统媒体库没有记录的录制补登记进相册。只看 7 天内的文件，一次最多处理 20 个，避免每次启动都爬一遍整个目录。完成后提示：

> 补登记 N 段录制到相册

两段都有结果时用「，」连接成一条提示。录制正在进行时会跳过。

## 录制失败时

| 情况 | 提示 |
| --- | --- |
| 启动失败 | 启动失败：… |
| 录制中出错 | 录制失败：… |
| 保存失败 | 保存失败：… |
| 高权限服务断开 | 高权限服务已断开 |

失败时状态会显示在主页与通知栏，并提供「查看」动作（如果已经产出了可播放的文件）。
